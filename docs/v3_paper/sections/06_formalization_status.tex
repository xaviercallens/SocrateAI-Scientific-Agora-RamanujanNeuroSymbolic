\subsection*{Three findings and why they are distinct}

The following findings differ in both severity and remedy.

\paragraph{Finding~1 (claim hazard, not build contaminant):
\texttt{NAMAGIRI\_legacy\_v1.lean}.}

The archived file
\texttt{dualscale/lean/archive/NAMAGIRI\_legacy\_v1.lean}
contains\,---\,and its header explicitly warns\,---\,the following vacuous
structures:

\begin{itemize}
  \item \verb|def Real := Float| and \verb|def Complex := (Float × Float)|,
    replacing the standard Mathlib types with floating-point stand-ins.
  \item Semantic predicates reduced to the tautology:
    \begin{itemize}
      \item \verb|def uniformBoundedness (D : EnstrophyFunctional) : Prop := True|
      \item \verb|def topologicalFracture (state : Complex) : Prop := True|
    \end{itemize}
  \item Theorems whose entire proof body is \verb|trivial|:
    \begin{itemize}
      \item \verb|theorem hypothesis_U_bound| (claims Hypothesis~U)
      \item \verb|theorem prevents_singularity| (claims discrete singular set)
    \end{itemize}
\end{itemize}

\noindent
\textbf{Severity.}
This file is a \emph{claim hazard}, not a \emph{build contaminant}.
It is imported by no production module and appears in no \texttt{lakefile}.
The kernel never sees it during compilation.
The hazard is documentary: a reader who cites the archive as evidence for
Hypothesis~U is citing a theorem proved by the axiom $\top$.

\noindent
\textbf{``Imported by nothing'' cuts both ways.}
The isolation that makes this file harmless to the build also makes it
invisible to any automated check.
A file that nothing imports cannot be caught by a lakefile build,
a \texttt{sorry} grep, or a CI gate.
This is why it survived, and why the \texttt{mathesis\_gate} vacuity
scanner (see \emph{Reproduction} below) was needed.

\subsection*{Connection to the cross-stream thesis}

The pattern across Streams~0--6 is as follows.
A stream declares a verification status (\textit{``Zero-Sorry''},
\textit{``machine-checked''}, \textit{``CI-gated''}), and that
declaration is not produced by the mechanism the reader would expect.
In RAMA-LS, three independent mechanisms contribute to the gap:
\begin{enumerate}
  \item An archived scaffold with vacuous proofs whose header warning
    is easily missed, and whose isolation from the build is exactly what
    prevents any automated check from catching it (Finding~1).
  \item A live tree with 2 \texttt{sorry}, 34 \texttt{axiom}, and at
    least one pinned constant\,---\,none of which prevents compilation,
    but each of which qualifies any Tier~A claim that depends on it
    (Finding~2).
  \item A README that names a CI file as the enforcement mechanism,
    while that file is not connected to a runner (Finding~3).
\end{enumerate}

RAMA-LS is the best-evidenced instance of this pattern in our corpus
precisely because all three sub-findings were confirmed in a single direct
session rather than reconstructed from subagent reports.
The distinction matters: an earlier audit (logged as LL-15) reported the
live-tree \texttt{axiom} count at a figure twenty times larger than the
actual~34, because the subagent had counted vendored Mathlib sources
inside \texttt{.lake/}.
That error was corrected by direct grep with the
\texttt{!\ -path */.lake/*} filter.

A second datum from the commit log is instructive.
Commit \texttt{e3a82fb} on \texttt{main}, titled
\textit{``zero-sorry Lean~4 verification,''}
is the commit that introduced \texttt{HolographicDemonstration.lean}\,---\,the
file containing the tree's only two \texttt{sorry} declarations.
The commit message and the commit contents are directly contradictory.
No adjective is needed: the fact speaks for the pattern.

\subsection*{Why this was not caused by a bad decision}

None of the findings above reflects a methodological error.
They reflect \emph{ordering}: the claims came first and the checking came
later.
The RAMA engine generates $\eta$-quotient candidates, the scaffolds
formalize them, and verification was always the final step.
That ordering is neither unusual nor wrong\,---\,it is how mathematics
has always been done.
The error is only that the status strings (``Zero-Sorry,'' ``CI-enforced'')
arrived at the same time as the scaffolds and stayed after the checking
stopped short.
This is already the argument in \texttt{NEW\_STREAM.md}, and putting it
here is what makes this section evidence for a general structural pattern
rather than an accusation directed at one tree.
